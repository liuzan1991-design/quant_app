### 0.1 由此产生的架构定则

| 定则 | 说明 |
|---|---|
| **策略侧 = 纯计算 + 原生 API + print** | 允许 `import time`；禁止 `os` / `pathlib` / `open()` / `requests` 等 |

## 2. 数据口径（全部实测，可直接照写）

| 项 | 事实 | 影响 |
|---|---|---|
| 1m 数据覆盖 | 2024 及以前**全为填充值**（300308 2024 年 58,322 根，成交量非零 **0** 根）；2025 仅约 43 天；2026 全量 | 1m 回测窗口最早 ≈ 2025 年末，2024 之前的 1m 回测不可信 |
| 日线覆盖 | 300308 自 **2023 年**才有真实数据（2023 年 185/242 天，2024 起完整）；2010/2015/2020 全零 | 日线级状态（MA/ATR/前收）只能回溯到 2023 |
| 填充值识别 | 填充行特征：`volume == 0` 且价格恒等于最新价 | **任何取数后必须先 `volume > 0` 过滤**，否则拿到的是假数据 |
| 日线索引 | **= 交易日 − 1 天**（3 处独立实证） | 读取后须 +1 天校正；根因是本机时区 GMT+3 导致北京时间 0 点回退一天（推测，未经服务端确认） |
| 1m 索引 | 按本机时区渲染：显示 `04:30:00` = 北京 09:30，`10:00:00` = 北京 15:00 | **禁止硬编码 ±5 小时**，须用 epoch 换算 |
| `count` 参数 | 语义 = "最后 N 根"，可跨日；**不能用于跨日取历史长区间**（早期版本实测只回当日） | 取历史一律 `start_time` + `end_time` + `count=-1` |
| `dividend_type` 默认值 | `ContextInfo.dividend_type` 默认 **`front_ratio`**（前复权·比例） | 必须显式传参，不能依赖默认值 |
| 复权口径 | `none` 出现机械跳空，`front`/`back` 连续；QMT 与 AD 因子差 **0.57%**（除权日比值 1.4034 vs 1.3955） | 与 H53 量级一致；跨源比对时需容忍 0.6% 级差异 |
| **分钟标签对齐** | **AD_label = QMT_label − 1 分钟**。2026-11-05 用 120 根已完成 bar 逐根比对：偏移 −1 时收盘 MAE **0.0000（120/120 完全一致）**，其余偏移 0.58~0.95 | 跨源合并必须先减 1 分钟；这是**实测结论**，非推断 |
| **成交量单位** | **QMT = 手，AD = 股**。同日量比 **0.0100 精确**，累计比 100.4 | 跨源比较一律 ×100 |
| ⚠️ **每日尾部缺口** | 当日最后 1–2 根**录不到**：收盘后无新 tick，handlebar 不再触发，最后一根永远等不到"下一个 bar 出现"。2026-11-05 缺 AD 14:58/14:59 | `tail_prev_day()` 在**次日首次 handlebar** 时补录前一日最后两根，输出 `TAIL,` 行；`qmt_log_export.py` 单独导出 `ro_tail_<日期>.csv` |

**取数模板（必须照此写）**：

```python
res = ContextInfo.get_market_data_ex(
    ['open', 'high', 'low', 'close', 'volume'], [code],
    period='1m', start_time=start, end_time=end,
    count=-1, dividend_type='none')
df = res.get(code)
df = df[df['volume'] > 0]          # 关键：过滤填充值
```

### 4.3 三个坑（必读）

1. **`POSITION.m_dAvgOpenPrice` = `1.7976931348623157e+308`（DBL_MAX 未初始化哨兵）**，不是价格。
   同理 `m_dStaticHoldMargin`。取成本价**只能用 `m_dOpenPrice`**。
2. 这些对象 `dir()` 会吐出大量枚举常量（`'0'`~`'255'`、`j/w/x/y/z`），
   字段遍历**必须按 `m_` 前缀过滤**。
3. 状态字段是 **ASCII 码整数**：`48='0'`、`51='3'`、`56='8'`。须按 QMT 枚举表映射，不能当 0/1/2 用。

### 4.4 持仓隔离（已拍板：与手工持仓共存于同一账户，必须隔离）

账户内既有策略持仓、也有手工持仓（实测 4 笔、市值 54,657；当日另有手工成交 001309）。
策略**绝不允许**根据"账户总持仓"决定卖出数量，否则会卖到用户手工买入的股票。

规则：
- 策略内部维护自己的持仓账本（沿用 `BrokerTAccount` 口径）。
- 卖出前校验 `可卖数量 >= 自有账本数量`，不足则该笔缩量或拒绝。
- 每笔发单带可追溯标识，收市后按 `m_strOrderRef` / `m_strTradeID` 对账。
- 2026-11-06 用户确认：可以同标手工交易。已核实的外部成交只更新外部数量，不计入策略仓、现金、全费用或收益；不得把缺标签的成交默认归为手工。正常外部交易不触发整策略停手，数量侵入策略仓、归属不明或对账缺失才阻断。
- 外部挂单的资金和可卖冻结以柜台当前可用值为准，不在策略账重复冻结。策略自己的T+1、底仓保护及账户真实可用资金下限保留。
- ⚠️ `ORDER.m_nStrategyID` / `POSITION.m_nStrategyID` 字段存在但语义未验证

  **暂不作为隔离依据**，需补测。

## 5. 资金与风控额度（已拍板：账户=真实账号，额度 base 锁 30 万）

> **账号决定（2026-11-04，Louis 拍板）**：将来策略直接跑在真实资金账户（总资产约 50.8 万），
> **不另开小资金账户**。因此资金与持仓必须做逻辑隔离，不得按账户总量放权。
> **额度口径（同日拍板）：策略自有权益固定锁 300,000**，不随账户 50.8 万浮动；
> 账户里超出 30 万的部分视为非策略资金，策略永久不调用。

策略自有权益按**固定 300,000** 计（不随账户总资产浮动），理由：既有回测/观察期全部以 30 万为分母，

| 项 | 值 | 依据 |
|---|---|---|
| 策略自有权益 base | 300,000 | 沿用既有 paper 口径 |
| 策略自有单标上限 `cross_symbol_cap` | 0.70 → 210,000 | 用户2026-11-06确认只算策略自有仓位和挂单，外部仓位不扣此额度 |
| 账户可用资金硬下限 | 210,000 | 低于此值视为"额度被手工交易占用"，策略停开仓 |
| 单笔委托金额上限 | 60,000 | 单标的最大仓位 ÷ 4（`max_position=200` × 约 255 元 ≈ 5.1 万） |
| 日内亏损熔断 | 3,000（自有权益 1%） | 沿用 `live_config.json` 现有设置 |
| 策略权益回撤熔断 | 15,000（5%），触发后全停 + 人工核对 | 新增，随 30 万口径生效 |

风险按策略账计算。全新、零自有仓的新实例允许在已核实的实际起点使用`risk_seed=origin_initialized`，以30万元作为初始权益、高点和日初权益，初始锁定为false；起点空历史不因缺少“起点之前的策略记录”被拒绝。起点之后必须转为持续检查点核验，不能靠重启重设初值；具体证据与字段见《状态重建方案》v0.4。真实可用资金是独立开仓约束，不等于记账本金。

> **逆回购与股票购买力口径修订于 2026-11-06。** `m_dAvailable` 为柜台当前可用金额。
> 迅投文档将 `m_dRepurchaseValue` 定义为“回购总市值，所有回购，期货没有”，
> 该值不能直接视为当前可买股票的现金，也不能直接认定为某日到期回款。
> 开盘前和每笔开仓前重读柜台真实可用资金，挂单按已核实的冻结语义计入额度。
> 逆回购未返还为可用现金的部分不扩充购买力，已经计入可用现金的部分也不重复相加。
> 盘后可用资金偏低只作当时诊断，不能据此判定下一交易日一定缺资。
> `m_dRepurchaseValue` 与 `m_dFrozenCash` 保留为诊断字段，到账与可用时点以柜台为准。

### 5.1 逆回购到期与待交收字段：只读诊断，待柜台实测

下列字段的定义已核对迅投官方文档；本终端是否提供、是否为有效值及到账时点尚未实测。文档有字段不等于当前柜台一定返回。

| 原始字段 | 官方定义 | 本项目允许用途 |
|---|---|---|
| `POSITION.m_strExpireDate` | 逆回购到期日 | 记录合同到期信息，安排到期前后只读核对；不能据此认定资金已返还或开盘可买股票 |

`qmt_builtin/snapshot_collector.py`为独立只读采集源码，仍为纯ASCII、仅import time、零文件/网络调用；24个下单/撤单函数拦截保留。任一次查询返回None、抛异常、账户行数异常、属性读取失败、必填字段缺失或为None，都使总结果`stable=False`；两轮失败结果相同只能叫`equal=True`，不能作为成功。

V2记录使用`[SNAP] V2 n=序号 kind=BEGIN/Q/D/END data=十六进制载荷`。载荷为保留类型的ASCII字面量，外部使用`ast.literal_eval`解析，不能用eval；备注中的空格、逗号、换行及中文无损编码。END记录前序记录数及校验和，外部还核对两轮四表、行号、字段数量和必填字段。校验和只检查丢失/损坏，不证明来源可信，也不替代本地原始日志留存。ACCOUNT/POSITION/ORDER/DEAL每行都核对原始账户ID，不能把掩码当唯一账号。

每次查询保留真实epoch起止；证据结束时间覆盖原生对象属性读取，另保留API调用自身结束时间和耗时。统一北京时间由epoch推导，不依赖本机时区，也不把旧快照改成当前时间。

`core/qmt_native_snapshot.py`负责沙箱外标准化和`rebuild_from_native_log`入口，连接现有`validate_snapshot`及`rebuild_from_snapshot`。**此文件、qmt_snapshot.py、qmt_account_monitor.py和qmt_state_review.py永远不得复制进QMT沙箱或由沙箱模块导入**；有中文、文件IO或外部依赖的模块都必须留在外部。

### 7.2 缺价与哨兵值：标准表示与判定（2026-11-07 实测后定规）

**事实**（2026-11-07 真实只读采集，样本 n=1，周六休市）：POSITION 共 4 行，其中逆回购残行 `131990.SZ` 的 `m_nVolume=0`、`m_nCanUseVolume=0`，而 `m_dLastPrice` 是 `1.7976931348623157e+308`（DBL_MAX 占位），两轮完全一致。同一份数据里 4 行的 `m_dAvgOpenPrice` **全部**是 DBL_MAX，含持有 2600 股的目标标的；成本价只能取 `m_dOpenPrice`（14.102），与 `readonly_301717.py` 既有注释一致。

**规则（对外契约）**

1. `mark_price` 类型为 `float | None`。`None` 表示柜台未给有效价格，只允许由 `DBL_MAX`、非有限值、`<=0` 触发；不得用 0、昨收或其它字段估算补齐。
2. 原始哨兵值不丢弃：整行原始字段仍参与 `native_fingerprint`，只是标准字段降级为 `None`；不删行、不改行数、不改字段数。
3. 判定表：

| 情形 | 处理 | 依据 |
|---|---|---|
| 目标标的、quantity>0、无有效价 | 停手，`native_target_mark_price_invalid` | 价格决定下单股数与止损，缺价不可决策 |
| 目标标的、quantity=0 | 不因缺价停手 | 无持仓即无该标的市值敞口 |
| 非目标、任意 quantity、无有效价 | 保留行，`mark_price=None`，记入 `unpriced` | 不参与策略决策，且不得据此算成 0 敞口 |
| 目标标的、quantity>0、价格有效 | 正常 | — |

4. `unpriced` 仅作可观测字段，**不阻塞**策略状态；但它一旦非空，就说明账户市值不完整，任何"敞口已解除"的表述都不成立。
5. 有股缺价**不等于**市值 0：下游若要算账户敞口，缺价行只能是"未知"，不得计入已定价合计后当作全量。

**为什么不是"过滤掉 0 股行"**：删行会让行数与证据口径失真，也抹掉"柜台确实返回了这只标的"这一事实。本次停手的原因是把整表当整体校验，问题不在某一行本身。

**复验**（同一份真实日志、同一真实校验时点 `14:59:57.439529+08:00`，未重打时间）：

| 项 | 修复前 | 修复后 |
|---|---|---|
| `valid` | false | **true** |
| `blockers` | `["native_invalid_schema"]` | `[]` |
| `unpriced` | 无此字段 | `["131990.SZ"]` |
| 131990 行 | 整表被拒 | 保留，qty=0，mark=None |
| 300319 行 | 读不出 | qty=2600，mark=14.01 |
| 快照 age / span | — | 0.0413 s / 0.0165 s |

同一份输入上另补了此前未走到的分支：`native_valid=True` 后传 `anchor/coverage/risk/as_of` 全为 `None` 的模板，结果 `mode=halt`、`blockers=["snapshot_as_of_or_mark_unverified"]`、`can_open=can_reduce=False`。即"标准化通过 ≠ 可交易"，缺业务证据仍停手。

**仍未验证（禁止外推）**：周六休市、ORDER/DEAL 空表、POSITION 仅 4 行，属最短路径样本；`span=16ms` 只能说明这一形态远低于 3 秒窗口，**不能**说明交易日长表也够用。`131990` 是否每日必现尚未证实，目前只知用户每日做逆回购、且本次为 0 股残行。

  （已知特性），而 QMT 同窗口有量。2026-11-04 / 11-05 实测对照：

  | 标的 | QMT bar（北京） | QMT 收盘 / 量 | 对应 AD bar | AD 收盘 / 量 |
  |---|---|---|---|---|
  | 300308 | 14:58 | 287.56 / **21 手 = 2,100 股** | 14:57 | 287.56 ✅ / **0** |
  | 301717 | 14:58 | 284.43 / **1 手 = 100 股** | 14:57 | 284.43 ✅ / **0** |
