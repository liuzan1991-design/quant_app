## 隔夜 T 仓归属

隔夜库存必须来自已核准的期初基准 anchor，并完整重放基准之后的成交。基准包含策略身份、标的、时点、虚拟现金、累计已实现盈亏、每批底仓或 T 仓的数量、含买入费用的单位成本、实际买入日期，以及同标的已核准的外部持仓量。

m_nYesterdayVolume 只作对账参考，不能直接等同于底仓。只有当日成交时，无法区分昨晚底仓与 T 仓。基准或历史缺失时返回 halt，T 仓数量为未知值 None。

- 买入订单的标准化意图为“建底仓”时进入底仓，“加权买入”前缀进入 T 仓。未分类的买入停止重建。
- 卖出按买入日期及 FIFO 分配，先前交易日 T 仓才可分配。新模块不会用底仓补足 T 仓卖出。
- 与现有 broker_driven 共用 sell_allocations。原 broker 的底仓兜底行为仍保留在其默认调用中，新模块显式禁用底仓兜底。
- 相同成交 ID 的相同回报只计一次，内容冲突则停手。成交与委托的方向、累计成交数量必须相符。
- 已核实为手工或其他外部归属的同标成交只重放外部数量，不改策略库存、现金、费用、收益及风控高点。外部买卖往返不会仅因发生手工交易而停手。
- 归属必须有独立来源。缺少标签的成交不能默认认作手工；owner为空、unknown等未知值时继续停手。外部数量不足以支持其卖出/挂卖，或总量无法对上时停手，避免把策略仓卖成负数。
- 期初之前已部分成交的跨日订单，还需 anchor.order_fills 提供期初累计成交量。
- 公司行为区间尚未在新模块重放。必须证明区间内无公司行为，或使用公司行为之后重新核准的基准，否则停手。既有复权和分红实现继续沿用。

委托标签、柜台成交 ID 范围及历史保留范围必须先完成只读实证。不要求用户停止同标手工交易，但“允许手工交易”不能把无标签成交自动变成已核实外部仓。V1 未通过、也无等价归属证据时，不能把 ownership_verified 置真。

外部台账只用于数量隔离和柜台对账，不核算用户手工策略的盈亏。外部成交无需向本策略提供手续费；fees_complete专指本策略自有成交全费用，orders_complete、deals_complete仍覆盖起点后的同标委托/成交，用来识别外部数量变化与遗漏回报。同交易日基准存在外部持仓时，anchor.external_bought_today必填，表示其中当日新买、仍受T+1锁定的数量。跨日后锁定释放，但不会变成策略仓。

### 期初基准的证据与核准

人工说明底仓/T仓用途属于待核准材料，不等于归属已经通过。现有买入须逐笔关联柜台成交编号、委托编号、原始买入日期、数量、完整费用及可核验来源，再核对策略现金、自有库存和已核准的同标的外部持仓。不能将账户全部持仓或昨仓量直接认领为策略底仓。

固定本金 300,000 元已经确定，不需要重新拍一个本金。待核准的是策略起点和期初批次、虚拟现金、累计已实现盈亏及其证据。期初批次可以含策略起点前买入的库存，必须保留实际 bought_on 和含费成本；不能把基准时点改成买入日期来绕过 T+1。

持续运行或恢复时，基准核准之后，coverage和risk仍需独立通过。不能因人工填表、签字或已阅，就自动把verified、ownership_verified、history_complete置真。缺已有策略的历史高点或熔断记录继续停手，不能靠另选时间清零。全新、零自有仓实例的空区间初始化按下文origin_initialized专门规则处理，不要求其起点之前存在本实例历史。

## 策略盈亏

固定初始权益为 300,000 元。本轮使用一个虚拟资金账计算该候选的权益。未来四策略合并时也只共用一笔 30 万资金，不能为四个调用各分配 30 万。

| 项目 | 计算规则 |
| --- | --- |
| 策略现金 | 期初虚拟现金，扣自有买入金额和全费用，加自有卖出净收入 |
| 策略权益 | 策略现金加自有剩余库存的当前市值 |
| 累计扣费收益 | 策略权益减 300,000 |
| 已实现盈亏 | 卖出净收入减 FIFO 分配到的含买入费用成本，并加期初已实现盈亏 |
| 未实现盈亏 | 剩余自有库存市值减含买入费用成本 |
| 当日盈亏 | 当前策略权益减已核准的当日策略起始权益 |

期初现金加库存成本必须等于初始权益加累计已实现盈亏，误差最多一分钱。费用必须是该成交归属的完整费用，不能未经核对就把单一 m_dCommission 当作所有税费。

账户总权益、其他股票盈亏、手工资金进出以及 m_dPreBalance 不用于计算策略收益。账户真实可用资金仅用于容量和硬下限检查。逆回购待回款不计入当前真实可用资金。

## 重启后的风控恢复

30 万本金、21 万单标的上限、21 万账户可用资金下限、6 万单笔上限、3,000 元日亏和 15,000 元回撤门槛均保留。退出只针对已核实可卖的自有 T 仓。

21万单标上限只扣策略自有库存市值及策略挂买额度，外部持仓不挤占此额度。正常外部挂单不加入策略挂单列表、冻结额或额度，但柜台available和sellable_quantity已经反映全账户真实冻结；仍须使用这些可用值，不再重复扣冻结，也不能因只算策略账就忽略真实购买力或可卖量。

risk 必须与此次策略身份、标的、交易日和时点一致。除当前权益外，还需核准的当日策略起始权益、历史权益高点、日亏锁定标志及回撤锁定标志。history_complete 表示从策略起点到本次时点的决策权益及熔断历史已核验。

### 新起点与持续风险记录

- `risk_seed=origin_initialized`只允许在`strategy_start = risk.as_of = anchor.as_of = 本次as_of`的实际初始化时点使用，且`risk.verified=true`、`origin_verified=true`。这是已核实的新实例起点，不要求起点之前存在本实例历史。
- 此时策略仓必须为空、期初策略现金/权益、日初权益和高点均为300000，初始已实现盈亏为0，两种锁定为false，输入中不能存在该实例的已有委托。外部数量另行核准，不可通过新起点把旧自有仓清掉。
- 上述起点条件通过后，空区间的策略历史自然完整，输出`risk_history_complete=true`；并不核准过去那些外部或归属未知交易的成本、用途。
- 第一次后续复算改用`risk_seed=risk_history_verified`和`history_complete=true`的完整风险检查点。旧输入不写risk_seed时沿用此持续记录模式，保持原接口行为。不能在起点之后反复传origin_initialized重置高点和锁定。
- 不使用账户总权益或手工交易盈亏生成策略高点，不凭空加设旧账户历史锁定；若输入已携带策略锁定，新起点不能清除它。未来若另有账户级风控，应作为独立已知约束，不伪造或混入策略历史。

- 日亏达到 3,000 元时只减仓不开仓，当日权益恢复也不能靠重启解锁。
- 回撤达到 15,000 元时停止全部决策。锁定标志保留，不能靠反弹或重启解锁。
- 缺少高点、起始权益、锁定标志或完整历史时完全停手。回撤限制不降级为外部展示。
- 新交易日必须取得新交易日的核准风险证据，不能复用前一日检查点。
- 未完成委托占用现金、仓位和额度，并等待其结束。部分成交只冻结剩余量。
- POSITION.sellable_quantity 和 ACCOUNT.available 规定为柜台已扣冻结后的可用值，避免重复扣减冻结。
- 下单结果未知、待报、未完成重启对账时停手。柜台尚未回显的在途请求不能靠空委托表证明不存在。

零文件和零网络条件下，若柜台不能提供完整历史，也没有合规来源的可信基准及风险证据，无法仅靠当日四张表恢复。模块拒绝恢复，不自动制造仓位或历史高点。

## 标准化输入合同

入口为 rebuild_state(account, positions, orders, deals, *, as_of, anchor, coverage, risk, mark_price, symbol, strategy_id)。金额和价格须有限、非哨兵值，数量须为非负整数。所有时间带时区，统一转换到北京时间。as_of 也是价格及四表的一致快照时点。

| 输入 | 必要字段 |
| --- | --- |
| account | available，柜台已扣冻结后的可用现金 |
| positions | 每标的一行 symbol, quantity, sellable_quantity |
| orders | order_id, symbol, owner, side, time, quantity, filled_quantity, status, reason；挂买单另需 limit_price, fee_reserve |
| deals | trade_id, order_id, symbol, side, time, quantity, price, fee |
| anchor | verified, symbol, strategy_id, as_of, cash, realized_pnl, external_quantity, lots；同日有外部仓另需 external_bought_today；跨基准部分成交另需 order_fills |
| anchor.lots | quantity, cost, kind, bought_on，kind 为 BASE 或 T |
| coverage | verified, from, to, deals_complete, orders_complete, positions_complete, fees_complete（策略自有全费用）, ownership_verified, corporate_actions_clear, submissions_reconciled |
| risk | verified, risk_seed, symbol, strategy_id, as_of, trading_day, equity, day_open_equity, high_water_equity, daily_loss_latched, drawdown_latched；持续模式需 history_complete=true；初始化模式需 origin_verified=true、strategy_start |

`POSITION.m_strExpireDate`、`ACCOUNT.m_dBuyWaitMoney` 和 `m_dSellWaitMoney` 登记为沙箱外的可选只读诊断材料，定义及待测要求见《移植规范》§5.1。它们不新增为本函数参数，不改变 account.available 的映射，不补足 anchor/coverage/risk。到期日不等于资金已可用，待交收金额不对柜台已计算的可用现金重复加减。

覆盖区间严格为 anchor.as_of 之后至 as_of。更早成交可以出现在输入中，但不会再计入。ID 需在账户、市场及证券范围内唯一。

标准委托状态为 working, partial, filled, cancelled, rejected, unknown, pending_submit。QMT 原始 ASCII 整数状态没有验证映射前不能直接传入。owner 必须来自已核验的标签或等价机制。标准化和取数适配层本轮尚未上线。

输出包括 mode, can_open, can_reduce, blockers，以及底仓和 T 仓、成本队列、可卖 T 仓、挂单占用、虚拟现金、扣费盈亏与风险状态。另含external_quantity、external_bought_today、external_pending_order_ids，symbol_cap_scope固定为strategy_owned；risk_seed与risk_history_complete说明风险证据来源。输出只用于离线判断。

## 离线验收和后续门禁

沙箱外的只读告警和人工已阅入口为 core/qmt_state_review.py，所有输出目录必须显式指定。它从标准化输入重新调用 rebuild_state，记录 halt、reduce_only 和 blockers，生成本地 ALERT_ACTIVE.txt 及 review_report.json。SQLite 台账保存复算与复核事实，文本及 JSON 可重新生成。

部署边界固定：QMT 沙箱内不得导入 core.qmt_state_review 或读写其台账；state_rebuild.py 不得为了读取核准表、告警或检查点而增加文件、网络或柜台调用。取证、格式转换和复核在外部完成，纯函数只计算调用方传入的证据。

人工已阅只追加复核人和意见，告警保持等待证据状态。已阅不修改重建输入、底仓归属、T+1、熔断锁定或交易权限，也没有放开底仓或解锁当日买入的参数。只有时点更新且全部证据重新计算通过的结果才能清除该范围的告警，旧快照或相同时点的冲突结果不能清除。同一时点只能维持或升级限制，新增阻断原因继续留档。不同标的和策略范围单独记录。
